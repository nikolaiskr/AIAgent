# AI Agent V3 — инструкция

## Что изменилось

V3 больше не рассматривает курсовую как один большой ответ модели. Курсовая хранится как долгоживущий проект:

```text
Project
├── project.json
├── requirements.json
├── work_plan.json
├── project_memory.json
├── sources.json
├── style_profile.json
├── input/
│   ├── methodology/
│   ├── assignment/
│   ├── literature/
│   ├── source_data/
│   ├── examples/
│   ├── feedback/
│   ├── current_version/
│   ├── author_style_sample/
│   ├── images/
│   ├── additional/
│   └── other/
├── sections/
│   ├── 00_introduction/
│   │   ├── v1.md
│   │   ├── v1.docx
│   │   ├── v1_review.json
│   │   ├── summary.md
│   │   └── metadata.json
│   ├── 1_1/
│   └── ...
├── work/
│   └── extracted/       # cache OCR/Vision
└── output/
```

Каждый раздел живёт отдельно, имеет версии и status. Сборка финального DOCX не перегенерирует работу заново.

## 1. Установка

Распакуй папку, затем запусти:

```text
setup.bat
```

Скрипт:

1. создаст `.venv`;
2. установит зависимости;
3. создаст **локальный** `config.env` из безопасного `config.example.env`, если `config.env` ещё нет.

В архиве `config.env` отсутствует.

## 2. Минимальный config.env

Для теста Telegram без нейросетей достаточно:

```env
PROJECTS_ROOT=C:/Users/ТВОЙ_ПОЛЬЗОВАТЕЛЬ/YandexDisk/Курсовые/
TELEGRAM_BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
```

OpenAI и DeepSeek можно оставить пустыми.

Для будущего гибрида:

```env
OPENAI_API_KEY=...
OPENAI_MODEL=...
OPENAI_VISION_MODEL=...

DEEPSEEK_API_KEY=...
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=...
```

Логика V3:

```text
DeepSeek → основной Writer / длинная генерация
OpenAI → анализ сложных файлов, Vision, Reviewer, Editor
Python → DOCX, графики, файловая структура, версии, сборка
```

Если DeepSeek не настроен, но OpenAI настроен, OpenAI может временно быть Writer-ом.

## 3. Перед запуском бота

Сначала рекомендуется:

```text
run_smoke_test.bat
```

Smoke test не вызывает нейросети. Он проверяет:

- создание проекта;
- project.json;
- role folders;
- requirements.json;
- fallback work_plan.json;
- sections/;
- version history;
- DOCX renderer;
- FinalAssembler.

После этого:

```text
run_bot.bat
```

## 4. Меню Telegram

### 🆕 Новая работа

Создаёт проект. Сначала выбирается тип:

- курсовая;
- ВКР;
- лабораторная;
- практическая;
- отдельное задание;
- другое.

У проекта сохраняется `owner_user_id`.

### 📁 Выбрать работу

Показывает только проекты, доступные текущему Telegram user. Старый проект без owner закрепляется за первым пользователем, который его открыл.

### 📋 Проект

Показывает:

- тип;
- тему;
- вариант;
- количество материалов;
- готовность;
- наличие плана;
- статус требований.

Можно вручную менять тему и вариант.

### 📎 Материалы

Можно отправлять в Telegram:

- PDF;
- DOCX;
- XLSX;
- TXT;
- MD;
- JPG/JPEG;
- PNG;
- WEBP.

Файлы сохраняются в `input/` и получают предварительную роль.

Через Telegram роль можно исправить. После ручного назначения файл переносится в соответствующую role folder.

Роли:

- methodology;
- assignment;
- literature;
- source_data;
- examples;
- feedback;
- current_version;
- author_style_sample;
- additional;
- images;
- other.

### 🗺 План

Если плана нет — создаётся `work_plan.json`.

Без AI используется безопасный fallback-шаблон. С AI Planner строит план на основании темы, задания и `requirements.json`.

План можно:

- перестроить;
- скачать;
- заменить валидным JSON вручную.

### 📝 Продолжить

Доступные сценарии:

- **Работа по разделам** — все pending разделы последовательно;
- **Отдельный раздел** — например только `1.2`;
- **Собрать главу** — объединить уже созданные подразделы без LLM-перегенерации;
- **Продолжить раздел** — взять текущую версию и создать новую;
- **Отдельное задание** — legacy one-shot режим для задач/математики.

### 📚 Разделы

На карточке проекта есть просмотр разделов.

Для раздела можно:

- скачать текущую версию;
- посмотреть историю версий;
- скачать предыдущую версию;
- отметить approved;
- продолжить;
- учесть замечание;
- создать, если версии ещё нет.

Предыдущие `v1/v2/v3` не перезаписываются.

### 💬 Замечания

Выбирается конкретный раздел и вводится замечание преподавателя. V3 создаёт новую версию только этого раздела.

### 📕 Собрать работу

`FinalAssembler` берёт последние версии уже созданных разделов и формирует единый DOCX.

Он **не просит LLM написать курсовую заново**.

По умолчанию сборка останавливается, если есть незавершённые/неapproved разделы. Можно явно подтвердить принудительную сборку.

После сборки формируется отдельный report consistency check.

### 🔍 Проверить

Проверяет выбранный DOCX. Локальная техническая проверка работает без AI. Если OpenAI подключён — добавляется проверка по методическим материалам.

### ⚙️ Диагностика

Проверяет:

- config.env;
- Telegram token;
- whitelist;
- реальный путь YandexDisk;
- права чтения/записи/удаления;
- soul.md;
- OpenAI;
- DeepSeek;
- Vision;
- зависимости;
- SQLite;
- pipeline settings.

### ❌ Отменить

Если идёт background Job, отправляет запрос cancel. Pipeline останавливается на ближайшем безопасном progress checkpoint.

## 5. Pipeline одного раздела

```text
Requirements
↓
WorkPlan
↓
ProjectMemory
↓
Section summary предыдущих частей
↓
BM25/keyword/role retrieval
↓
SourceRegistry
↓
Writer
↓
Citation Validator
↓
Internal Similarity Checker
↓
Reviewer
↓
Editor (до MAX_REVIEW_LOOPS)
↓
NaturalAcademicEditor
↓
Final Reviewer
↓
Version save
↓
summary.md
↓
ProjectMemory update
↓
DOCX
```

Reviewer возвращает score. По умолчанию целевой threshold — 85.

## 6. SourceRegistry

Литература и дополнительные источники получают ID:

```text
SOURCE_001
SOURCE_002
```

Writer должен использовать только такие ссылки:

```text
[SOURCE_001]
```

Citation Validator проверяет, что ID реально существует.

При финальной сборке renderer превращает SOURCE ID в цифровые ссылки.

Если metadata источника не распознана, система не придумывает автора/название: используется имя реально загруженного файла.

## 7. ProjectMemory

Хранится в:

```text
project_memory.json
```

Содержит:

- объект/предмет;
- цель;
- задачи;
- терминологию;
- организацию;
- период;
- важные числа;
- согласованные определения;
- ключевые claims.

Следующая глава получает память + summaries, а не весь предыдущий текст целиком.

## 8. NaturalAcademicEditor

Этап предназначен для улучшения качества академического русского:

- уменьшает шаблонные вводные;
- убирает чрезмерный канцелярит;
- разнообразит синтаксис;
- убирает бессодержательные абзацы;
- уменьшает ненужные повторы;
- сохраняет точную терминологию.

Он получает прямой запрет менять числа, названия, выводы, SOURCE_ID и добавлять новые факты.

Если загружена прошлая работа с ролью `author_style_sample`, создаётся `style_profile.json`. Конкретные фразы из примера копировать запрещено.

## 9. AcademicDocxRenderer

Fallback AcademicPreset:

- Times New Roman;
- основной текст 14 pt, black;
- Heading 1 — 17 pt bold black;
- Heading 2 — 16 pt bold black;
- Heading 3 — 14 pt bold black;
- абзац 1.25 см;
- выравнивание по ширине;
- A4;
- интервал 1.5.

Если `requirements.json` содержит параметры из методички, именно они имеют приоритет.

## 10. OCR / Vision

Текстовые PDF читаются локально.

Если PDF похож на скан и OpenAI Vision настроен:

```text
PDF → render pages → OpenAI Vision → cached text
```

Фотографии:

```text
JPG/PNG/WEBP → OpenAI Vision → cached text
```

Vision cache хранится в `work/extracted/`, чтобы один и тот же файл не отправлялся в API повторно без необходимости.

Без OpenAI фотографии просто сохраняются и не ломают проект.

## 11. Очередь

V3 содержит локальный `JobManager`:

- ThreadPool worker;
- SQLite job status;
- progress;
- cancel.

Это уже убирает большие операции из Telegram event loop.

Для нескольких серверов/worker-нод этот интерфейс в production следует заменить Redis/RQ/Celery. В текущем ZIP Redis специально не обязателен, чтобы проект можно было протестировать на одном Windows-компьютере без дополнительной инфраструктуры.


## 13. Что специально не включено в архив

В ZIP **нет**:

- `config.env`;
- `.env`;
- API keys;
- Telegram token;
- SQLite database с реальными пользователями;
- logs;
- `.venv`.

Есть только `config.example.env`.
