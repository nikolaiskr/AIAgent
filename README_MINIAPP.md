# AI Agent V3 — Telegram Mini App

Нео-бруталистский веб-интерфейс поверх того же пайплайна, что и бот: проекты-папки, материалы, план, разделы с версиями, сборка, админка и окно оплаты.

## Как это работает

- `webserver.py` поднимается вместе с ботом (`bot.py → main()`) и слушает `MINIAPP_HOST:MINIAPP_PORT` (по умолчанию `127.0.0.1:8080`).
- Статика лежит в `webapp/` (`index.html`, `styles.css`, `app.js`).
- Авторизация — стандартная валидация Telegram WebApp `initData` (HMAC-SHA256 с токеном бота). Вход возможен только из Telegram.
- Все тяжёлые операции уходят в тот же `JobManager`, что и бот: фронтенд получает `job_id` и поллит `/api/jobs/<id>` раз в 2 секунды.

## Запуск

1. Установи зависимость: `pip install aiohttp` (добавлена в `requirements.txt`).
2. Заполни в `config.env`:
   - `ADMIN_IDS` — твой числовой Telegram id (команда `/id` в боте). Без него не работают пуши и админка.
   - `MINIAPP_URL` — публичный **HTTPS** адрес приложения.
3. Запусти бота (`run_bot.bat`). Сервер Mini App стартует автоматически; в логе будет строка `Mini App сервер запущен`.
4. В Telegram: `/start` → бот предложит приложение и закрепит его в меню чата (кнопка слева от поля ввода). Также работает команда `/app`.

## HTTPS для Mini App

Telegram требует HTTPS для Web App. Варианты:

- **Cloudflare Tunnel (проще всего)**: `cloudflared tunnel --url http://127.0.0.1:8080` → получишь `https://….trycloudflare.com` и вписываешь его в `MINIAPP_URL`.
- **ngrok**: `ngrok http 8080`.
- Свой домен + reverse proxy с TLS.

Для локальной разработки без Telegram: запусти бота, открой `http://127.0.0.1:8080/?dev=1` при `DEV_MODE=1` — вход будет от имени пользователя с id 1 (сделай его админом через `ADMIN_IDS=1`).

## Оплата

- Пользователю доступно `FREE_PROJECTS` бесплатных работ (по умолчанию 2).
- Когда лимит исчерпан, в момент **создания новой работы** всплывает окно оплаты: кнопка «Написать владельцу» + «Я написал». Владельцу приходит пуш с id пользователя и готовой командой `/paid`.
- Подтверждение оплаты — двумя способами:
  - в боте: `/paid <user_id>` (навсегда) или `/paid <user_id> 30` (на 30 дней), `/unpaid <user_id>` — отозвать;
  - в Mini App: панель владельца (⚙️) → кнопка «✅ Оплачено» напротив пользователя.
- Пользователь мгновенно получает сообщение об открытии доступа.

## Пуш-уведомления владельцу

При `ADMIN_IDS` и `NOTIFY_JOB_EVENTS=1` владелец получает:

- 🆕 новый пользователь (первый `/start`);
- ✅ / ❌ / ⛔ завершение, ошибка или отмена каждого job'а (вид работы, проект, длительность, текст ошибки, код `ERR-XXXX` для поиска в `logs/agent.log`);
- 💰 запросы оплаты с готовой командой подтверждения;
- 🐛 необработанные ошибки бота и API Mini App.

Все события дублируются в ленту «📟 Лента событий» в панели владельца + таблица `events` в `data/aiagent.db`. Расход токенов API — в панели владельца (таблица `usage`).

## API (кратко)

Все эндпоинты под `/api/` требуют заголовок `X-Telegram-Init-Data`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/me` | пользователь, квота, права админа |
| GET/POST | `/api/projects` | список / создание (402 PAYWALL) |
| GET | `/api/projects/{name}` | карточка: материалы, план, разделы |
| POST | `/api/projects/{name}/upload` | загрузка файла (multipart) |
| POST/DELETE | `/api/projects/{name}/materials[/role]` | роль / удаление |
| POST/PUT | `/api/projects/{name}/plan` | создать/перестроить / заменить JSON |
| POST | `/api/projects/{name}/sections/{sid}/{action}` | generate · continue · revise |
| POST | `/api/projects/{name}/chapter` · `/assemble` | сборка главы / всей работы |
| GET/POST | `/api/jobs[/{id}[/cancel]]` | статус, список, отмена |
| GET | `/api/download?project=&path=` | скачивание DOCX/файлов |
| POST | `/api/payment/request` | запрос оплаты → пуш владельцу |
| GET | `/api/admin/users` · POST `/api/admin/users/{id}/paid` | админка: пользователи, доступ |
| GET | `/api/admin/events` | лента событий + токены |

## Что починено в ядре (V3.1)

1. **Отмена job'ов реально работает**: `JobCancelled` больше не глотается `_progress` в `pipeline.py`.
2. **Статус `writing` не застревает**: обёртка `generate_section` возвращает предыдущий статус при отмене и ставит `needs_revision` при любой ошибке.
3. **Retry/backoff провайдера**: до 4 попыток с паузами 2/4/8/16 с на rate-limit, обрывы сети и 5xx.
4. **Детект обрезки ответа**: `finish_reason='length'` → понятная ошибка, а не обрезанная версия раздела.
5. **Кэш извлечения текста** по fingerprint (путь+размер+mtime) — материалы больше не перечитываются на каждый раздел.
6. **Блокировка проекта**: по одной активной задаче на работу (`ProjectBusyError`), отменяются все job'ы пользователя разом.
7. **Ротация версий**: хранится `VERSION_KEEP` последних версий раздела, старые файлы удаляются.
8. **SQLite WAL** и один UPDATE вместо SELECT+INSERT при каждом шаге прогресса.
9. **Учёт токенов** по моделям (таблица `usage`).
10. Пуши владельцу о событиях, биллинг, окно оплаты и админ-панель (см. выше).
